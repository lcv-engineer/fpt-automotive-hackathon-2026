🌐 2. Sử dụng REST API của SOVD Service

Tất cả endpoint chính dùng prefix /maaz_sdv_vss/v1. Hầu hết API yêu cầu JWT Bearer token, ngoại trừ một số endpoint public/guest do BTC cấu hình.

Authentication

POST /maaz_sdv_vss/v1/user/login
Authorization: none
Body: { "username": "...", "password": "..." }
Response: { "token": "<jwt-token>", ... }

Vehicle

GET /maaz_sdv_vss/v1/vehicle/get_all
GET /maaz_sdv_vss/v1/vehicle/get_vehicle?vinid=<VIN>
Authorization: Bearer <token>

SOVD Request

POST /maaz_sdv_vss/v1/sovd_request
Authorization: Bearer <token>
Content-Type: application/json
{
  "Common": { "Vin": "<VIN>" },
  "ServerRequest": {
    "RequestData": {
      "Method": "GET",
      "Path": "/components/...",
      "Body": "{}"
    }
  }
}
Lưu ýPayload thực tế có thể khác theo version source code BTC cung cấp. Khi nhận source sovd_service, đội thi cần ưu tiên xem file model/handler hoặc sample request đi kèm.

📡 3. MQTT Topics

SOVD Service đóng vai trò bridge: nhận REST request từ team application, publish MQTT tới Vehicle theo VIN, chờ response rồi trả kết quả về HTTP client.

TopicChiềuMục đích
aws/maaz_sdv_sovd/sovd_request/{vinid}Server → VehicleChuyển tiếp SOVD request tới xe.
aws/maaz_sdv_sovd/sovd_response/{vinid}Vehicle → ServerVehicle trả SOVD response.
aws/maaz_sdv_sovd/vehicle_sw_update_request/{vinid}Server → VehicleThông báo software update.
aws/maaz_sdv_sovd/bulk_data_v2c_request/{vinid}Server → VehicleYêu cầu Vehicle upload dữ liệu.
aws/maaz_sdv_sovd/bulk_data_c2v_request/{vinid}Server → VehicleGửi URI download tới Vehicle.
aws/maaz_sdv_sovd/remote_request/{vinid}Server → VehicleGửi lệnh điều khiển từ xa.
aws/maaz_sdv_sovd/remote_response/{vinid}Vehicle → ServerPhản hồi trạng thái command.

🧪 7. Test & Debug

  • Kiểm tra API login và token trước khi gọi endpoint cần auth.
  • Kiểm tra VIN đúng với Vehicle/Room được BTC cấp.
  • Kiểm tra service logs khi request timeout hoặc MQTT không có response.
  • Test happy path và failure path: sai VIN, vehicle offline, DTC rỗng, OTA package không tồn tại, command rejected.
  • Nếu dùng AI, chuẩn bị fallback response khi API nền tảng hoặc model bên ngoài không khả dụng.
3 Deploy & nộp bài

Từ source code đến image chạy được trên CarSky và bộ hồ sơ submission.

✅ 1. Yêu cầu trước khi deploy

  • Source code build thành công trên máy local/container.
  • Có Dockerfile hoặc hướng dẫn build image rõ ràng.
  • Các biến môi trường như API URL, MQTT broker, database, token, secret không hard-code trong source.
  • README mô tả rõ kiến trúc, chức năng, cách build, cách chạy local và cách deploy CarSky.
  • Đã test tối thiểu các API chính bằng Postman/curl/script tự động.

🐳 2. Build Docker image

Build local

docker build -t team-sdv-sovd-app:latest .
docker run --rm -p 8080:8080 team-sdv-sovd-app:latest

Build multi-arch và push thẳng registry

docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t registry.hackathon-1.carsky.io/<team>/app:latest \
  --push .
RegistryThay registry URL, namespace, username/password và image name theo thông tin chính thức BTC cấp cho từng đội.

🚀 3. Push & Deploy lên CarSky

docker login registry.hackathon-1.carsky.io
docker tag team-sdv-sovd-app:latest \
  registry.hackathon-1.carsky.io/<team>/team-sdv-sovd-app:latest
docker push registry.hackathon-1.carsky.io/<team>/team-sdv-sovd-app:latest

Sau khi image đã có trên registry, đội thi thực hiện deploy bằng UI/workflow của CarSky hoặc manifest do BTC cung cấp.

  • Deployment ở trạng thái Running.
  • Service khởi động thành công và không bị restart liên tục.
  • API của service đội thi có thể truy cập được.
  • Kết nối tới SOVD Service và MQTT/Vehicle hoạt động đúng.
  • Logs không có lỗi nghiêm trọng trước khi demo.

❓ 7. FAQ

Đội thi có bắt buộc dùng Adaptive AUTOSAR không?

Không bắt buộc. Adaptive AUTOSAR là hướng nâng cao cho đội muốn làm sâu phía Vehicle/HPC. Các đội vẫn có thể làm dashboard, AI service, backend hoặc agent tích hợp SOVD API.

Đội thi có cần tự dựng MongoDB, MinIO, Mosquitto không?

Thông thường không cần nếu BTC đã cấp sẵn CarSky/SOVD environment. Nếu chạy local để debug source sovd_service, có thể dùng compose.yml đi kèm source.

API gọi bị timeout thì xử lý thế nào?

Kiểm tra token, VIN, Vehicle trạng thái online, MQTT response topic và logs của sovd_service. Nếu chỉ một số path lỗi, khả năng Vehicle chưa support path đó.

Push image lên registry bị lỗi credential?

Kiểm tra đúng registry URL, username/password/token, namespace image và quyền push của đội. Nếu dùng buildx multi-arch, đảm bảo lệnh có --push và Docker builder đã sẵn sàng.

Nên làm bài theo hướng nào để có điểm mới?

Không nên chỉ làm Gateway thông thường. Nên mở rộng sang AI Agent, Validator, Security, Fleet Analytics, OTA workflow, Digital Twin hoặc SOVD Data Server để thể hiện tầm nhìn sản phẩm.
